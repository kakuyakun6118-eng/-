# Version 51 の報告(軍団の帰城・都市の駐屯兵力の上限の撤廃・軍団結合)

この文書の「確かめた」は、すべて**開発環境の自動テスト**(Playwright・ソフトウェア描画の Chromium。iPhone は画面の大きさとタッチの模擬)と、**開発環境での長い通し**の結果です。**実機(LG gram・iPhone)では確かめていません。**実機の手順は docs/v51-device-test.md にまとめました。

## 1. 実装の結果

### 1-1. 軍団の帰城

- 軍団の操作に**「帰城」**を加えました。押すと、帰城先の一覧が出ます。
  - 「出発元」「最寄り」「首都」の印と、ほかの自国の都市(近い順)。
  - それぞれ、実際の道のりの距離・日数・道中の兵糧の消費・着いたときの残りの兵糧を示します(道が無い都市は出しません)。
- 都市を選ぶと、地図に道のりが出ます。「確定」で帰城を始めます。軍団は、これまでの道・地形・関所・補給の仕組みで進みます(瞬間移動しない)。すぐそば(約35km以内)の都市は、その場で入城します。
- 着いたときの処理(src/sim/Campaign.ts の `absorbIntoCity`):
  - **兵**:兵種別(歩兵・騎兵・弓兵)に、都市の守備兵へ加えます。都市は、守備兵の兵種の内訳を持つようにしました(`garrisonMix`)。攻城戦の守備隊・次の出陣・補充も、この内訳を使います。
  - **兵糧**:残りの食糧を、出陣のときと同じ割合で国の蔵へ戻します。
  - **武将**:指揮官・副将・配下武将を、その都市へ戻します。
  - **士気・疲労**:士気は、兵の数で重みをつけて都市の士気と平均します。疲れた兵は、そのぶん士気を下げて加わります。
  - **確かめてから消す**:守備兵が軍団の兵の数だけ増えたこと、武将が都市に移ったことを確かめてから、軍団を地図から消します。
- 帰城できない場合:

| 場面 | 処理 |
|---|---|
| 帰城先が敵に奪われた | 帰城を取り消し、「別の帰城先を選んでください」と示す。もう一度「帰城」で選べる |
| 道が塞がれた | 道を探し直す(4回まで)。見つからなければ取り消す |
| 途中で敵と出会った | ふつうの会戦になる。決着後に生き残っていれば、道を探し直して帰城を続ける |
| 帰城先が包囲されている | 入城せず、城外で待つ(救援軍として加わる)。包囲が解けたら入城する |
| 軍団が壊滅した | 軍団が消えるので、命令も消える |
| 国が滅んだ | 滅んだ国の軍団は消える(これまでの処理) |

### 1-2. 都市の駐屯兵力の上限の撤廃

- 都市の規模ごとの守備兵の固定の上限(例:建康の規模で2万人)を、**駐屯の上限としては使わない**ようにしました。帰城した兵は、何人でも駐屯できます(10万人+5万人=15万人を確かめました)。
- 募兵(新しく集める兵)は、これまでどおり「守備兵が人口の6%になるまで」です。これは駐屯の上限ではなく、その都市で集められる数の上限です。
- かわりに、兵站で抑えます。
  - **兵糧**:守備兵の兵糧の消費は、これまでどおり兵の数に比例します。人口に見合わない大軍のいる都市は、周りから運ぶ分も兵糧がかかります。
  - **費用**:守備兵の維持費は、これまでどおり兵の数に比例します。
  - **過密**:人口の6%を超える兵がいる都市では、治安と繁栄(衛生)が少しずつ下がります。下がり方は1か月に治安が最大3、繁栄が最大1.5です。上限も過密の度合いで下がりますが、急には下げません。
  - **兵糧の不足**:国の兵糧が尽きると、守備兵の士気が下がって戻らなくなります。人口に見合わない分から、毎月5%が脱走します。
  - 以前の「帰農」(人口の6%を超えた分が、毎月4%ずつ田畑に帰る)は、実質的な上限になっていたため、兵糧が尽きたときの脱走に置き換えました。
- **攻城戦**:
  - 守備兵の総数は、攻城戦の守備兵力にそのまま入ります。
  - 城壁の上と城門に同時に立てる兵の数は、城の規模で決まります(`wallCapacity`:城の防御力と城門の数から。例:城門3・防御60で約4万2千人)。
  - 3Dの攻城戦では、城壁の上の弓兵をこの数で抑え、超えた分は城内の予備にします。
  - 自動戦闘では、これを超えた分の効き目を35%にします。
  - **駐屯兵力の総数と、戦場で同時に戦える数は別**です。

### 1-3. 軍団結合

- 軍団の操作に**「軍団結合」**を加えました。
  - 同じ国の軍団の一覧(兵の数・指揮官・距離)から、結合する軍団を選びます(複数可)。
  - 結合後の総指揮官を選びます(どちらかの指揮官か、同行している武将)。
  - 決める前に、結合後の兵力(兵種別)・兵糧・士気・疲労・行軍の速さ・総指揮官・副将・配下武将の見込みが出ます。
- 結合の条件:同じ国の軍団、戦闘中でない、道がある。
  - 近く(約40km以内)の軍団は、その場で結合します。
  - 離れた軍団は、結合先のそばまで進んでから結合します(瞬間的な結合はしない)。
  - 結合先は、合流を待つあいだ止まります。
- 結合の計算:
  - **兵種別の人数**:そのまま足します。兵の合計が合わなければ結合しません。
  - **兵糧・士気・疲労**:兵の数で重みをつけて平均します(例:3万人・兵糧60日分・士気80と、2万人・30日分・士気50 → 48日分・士気68)。
  - **位置・行軍の命令**:結合先のものを引き継ぎます。補給の状態は、毎日の計算で決まります。
  - **事件の印**(歴史の会戦の印):結合先へ移します。
- **武将**:総指揮官のほかの武将は、副将か**配下武将**(新しく設けた欄)になります。能力・忠誠・人物関係は変えません。
  - 配下武将は、人物の役目に「〇〇軍 配下武将」と出ます。所在は軍団と同じに扱います。
  - 毎日、死亡・捕虜・寝返り・ほかの役目についた武将は、配下から外します。
- **大軍団**:人数の固定の上限は設けていません。かわりに、次の影響があります。

| 影響 | 内容 |
|---|---|
| 行軍 | 2万人を超えると遅くなる。統率の高い指揮官ほど遅れは小さい。山地ではさらに遅い |
| 補給 | 3万人を超えると、補給の届かない所では食糧の減りが速く、補給の届く所でも蓄えの戻りが遅い |
| 指揮 | 指揮官が十分に動かせる数(2万人+統率×400人)を超えた分は、自動戦闘での効き目が半分になる。3Dの会戦では、展開に手間取り、士気が少し下がる(最大-10) |

  大軍団ほど必ず有利、にはなりません。

### 1-4. AI

AIの国も、帰城と軍団結合を使います(src/sim/strategy.ts の 1b〜1d)。

| 場面 | 使い方 |
|---|---|
| 消耗した軍団 | 兵が最小の軍団の7割未満なら、近くの自国の都市へ帰城する |
| 戦争の無い国・後方の軍団 | 出陣から半年たった小さな軍団を帰城させる(いちばん大きい軍団は残す) |
| 再編成 | 近く(120km以内)の手の空いた小さな軍団を結合する(以前は、片方を解散して兵だけ移していた) |
| 首都の防衛 | 首都に敵が迫ると、首都の近くの2つの軍団を、首都に近いほうへ結合する(4万人まで) |
| 大軍団の編成 | 攻めの方針のとき、400km以内の手の空いた軍団をいちばん大きい軍団のもとへ呼び寄せて結合する(5万人まで、国ごとに半年に1度まで) |

すべてを1つにまとめないよう、大軍団の編成は軍団を3つ以上持つ国だけが行います。首都の近く(80km以内)の軍団は呼びません。守備兵には手を付けないので、首都が空になることはありません。

帰城・結合中の軍団は、ほかの作戦に使いません。

## 4. 既存の未解決問題(新しい機能とは別に)

### 4-1. 捕虜の記録と人物の状態がずれる問題:根の原因を突き止めて直した

記録の書き換えを、すべて追跡する通しで調べました(383年から21年。読める版でビルドし、人物の状態と捕虜の記録の書き換えを、呼んだ処理の名前とともに記録)。

**見つかった流れ**(郗璿・何法倪):

1. 387年、前秦が東晋の都市を落とす。2人は「住まい」がその都市だったので「保護」になる。
2. しかし、2人は**別の都市の太守の欄に名前が残ったまま**だった。保護・捕虜になっても、太守の任を外していなかった。
3. 388年、その別の都市も攻城戦で落ちる。2人は太守として**2度目の捕縛**を受け、状態が「保護」から「捕虜」に上書きされた。陥落の処置が、重なりを確かめずに**捕虜の記録をもう1つ作った**。
4. そのあと、登用や解放で記録が1つだけ消え、もう1つが残る。状態は「健在」なのに、捕虜の記録がある。

**根の原因は3つ**でした。

| 原因 | 直したこと |
|---|---|
| 捕虜・保護になっても、太守・指揮官・副将の任を外していなかった | 新しい `vacatePosts`。捕虜・保護・殺害(簒奪)になったとき、すべての役目を外す。会戦の捕縛・落城・国の滅亡・移動中の捕縛・歴史の事件の捕縛で使う |
| 落城で、住まいがその都市の人を、実際の所在に関係なく捕らえていた(別の都市の太守や、出陣中の武将も) | その場に実際にいる人だけを捕らえる(`presentAt`) |
| 捕虜の記録の追加・削除が、二重を考えていなかった | 陥落の処置で、すでに捕虜・保護の人や、処置を待つあいだに亡くなった人には記録を作らない。解放・死亡では、その人の記録をすべて消す。会戦の捕縛で、すでに捕虜・保護の人の状態を上書きしない |

あわせて、同じ調べで見つけた次の不具合も直しました。

- 簒奪で殺された君主が、副将のまま残っていた(357年:苻生が苻堅軍の副将のまま)。
- 歴史の事件で国を移った人が、元の国の軍団の副将・太守のまま残っていた。

**直したあとの確かめ**:同じ追跡を8シナリオすべてで流しました(合わせて約100年)。

| 確かめたこと | 結果 |
|---|---|
| 二重の記録・状態のずれ | 0件 |
| 毎月の片づけで直した件数 | 0件 |

毎月の片づけは安全策として残しました。直した件数を数えるようにしたので、根の原因が残っていないことを確かめられます。

### 4-2. 歴史の事件のうち、史実の結果を直接確かめられていないもの

新しく「史実に導く通し」を作りました。

- AIの選択も史実どおりにする。
- 事件の会戦は、両方の勝ち方を試し、史実の結果になる側を採る(試す前の状態に戻してから採るので、二重には反映されない)。

**史実の結果を直接確かめられた事件**:**36件 / 57件**(前回は34件)。

- 確かめた方法:開始時の試行(テスト34)・前回と今回の通し・史実に導く通し・テスト33(永嘉の乱)。
- 史実に導く通しで、新たに確かめられた事件:淝水の戦いのあとの連鎖、慕容皝の即位と慕容仁の反乱、丸都の陥落など。
