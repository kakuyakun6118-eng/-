# Version 42 追加修正の報告(戦う側・戦闘のスキップ・歴史イベントの反映)

この文書の「確かめた」は、すべて**開発環境の自動テスト(Playwright・ソフトウェア描画の Chromium)**での結果です。**実機(LG gram・iPhone)では確かめていません。**

## 1. プレイヤーの戦う側(最優先)

### 原因

会戦の準備画面を開くたびに、操作する側を「攻撃側」に戻していました。さらに「指揮:攻撃側/防御側」の釦で、どちらの側にも切り替えられました。そのため、前趙が東晋の城を攻めると、東晋のプレイヤーが前趙の攻城側を指揮する状態になっていました。

あわせて、3Dの戦場で部隊を選ぶ処理が、敵の側の部隊も選べてしまう不具合がありました(テストで見つけて直しました)。

### 直したこと

- 戦う側を決める処理を1つにしました(src/sim/battle.ts の `playerSideOf`)。プレイヤーの国(と、加勢・救援に加わったプレイヤーの軍団)を、攻撃側・防衛側の国と照らし合わせて決めます。軍団の並び順や、処理を呼んだ順では決めません。
- 準備画面と、会戦を始める処理の**両方**で、この判定を使います。通常のプレイでは切り替えの釦を使えなくし、「あなたの陣営:守城側」のように表示します。観賞・編集モードだけ、切り替えられます。
- 準備画面に、攻撃側・防衛側の国と、どちらがプレイヤーかを表示します(例:「攻撃側:漢(前趙)(AI) / 防衛側:晋(東晋)(プレイヤー) / あなたの陣営:守城側」)。
- 3Dの戦場の上の帯に、両軍の名前とともに「(あなた)」「(AI)」を出します。
- 3Dの戦場では、プレイヤーの側の部隊だけを選べます。

### 確かめた結果(テスト33)

| 場面 | 結果 |
|---|---|
| 前趙が東晋の都市を攻める | 守城側。切り替え不可。守る側の命令が出る。前趙の部隊は選べない |
| 東晋が前趙の都市を攻める | 攻城側 |
| 東晋が野戦を仕掛ける | 攻撃側 |
| 前趙が東晋に野戦を仕掛ける | 防衛側 |
| AIどうしの攻城戦 | 準備画面は開かず、自動で処理(包囲の日数ののち決着) |
| 「攻撃側で始める」と直接頼んでも | 守城側になる |
| 戦闘の準備中にセーブ・ロード | 準備画面に戻り、守城側のまま |
| 戦闘のあと | 戦略マップに戻り、会戦は決着済み |

プレイヤーが敵の側の軍団を指揮した件数は0件でした。

同盟軍の援軍は、Version 42 の救援軍の仕組みで扱います。プレイヤーの都市の救援に加わった軍団は、守る側(プレイヤーの側)として戦場に出ます。

## 2. 野戦・攻城戦のスキップ

- 準備画面の釦は3つになりました。
  - **「手動で指揮」**:3Dの戦場で指揮する(これまでどおり)。
  - **「自動戦闘」**:AIどうしの会戦と同じ計算(autoResolve)で結果を決め、結果を知らせに示してから戻る。
  - **「戦闘をスキップ」**:同じ計算で結果を決め、すぐ戦略マップへ戻る。
- 3Dの戦場には **「残りをスキップ」** を置きました。確認ののち、その時点の状態をそのまま引き継いで、両軍をAIに任せ、同じ戦闘の計算で最後まで進めます。引き継ぐもの:残りの兵・士気・疲労・兵糧・指揮官の状態・城門と城壁の傷み・部隊の配置・救援軍の到着の状況・地形と渡河。開始時に戻して計算し直すことはしません。
- 結果は、手動の会戦と同じ処理で戦略マップへ反映します(勝敗・損害・指揮官の生死と捕縛・都市の占領・城壁・撤退・救援軍の損害・首都の陥落・君主の捕縛・国の滅亡・歴史の事件)。

### 確かめた結果(テスト33)

| 場面 | 結果 |
|---|---|
| 攻城戦の途中のスキップ | 30秒戦ったあとで押すと、確認が出て、時刻は31秒から1,435秒まで進んで決着。兵は51,099から37,933へ |
| 結果の二重の反映 | 同じ結果をもう一度反映しても、軍団は変わらない |
| 野戦の開始前のスキップ | 結果が軍団に反映され、準備画面は閉じる |
| 首都の攻城戦(救援軍の処理つき)を自動戦闘で | 建康が陥落し、首都の陥落の処理が1度だけ動いた |
| 歴史の事件の会戦をスキップ | 永嘉の乱の洛陽の攻城戦(下の3) |
| スキップのあとのセーブ・ロード | 結果が残る |

自動戦闘とスキップの計算は、Version 42 の救援軍の決まり(着く前に決着すれば加わらない)を含みます。

## 3. 歴史イベントの結果の反映

### 永嘉の乱で見つかった不具合と、直したこと

1. **会戦の結果を読む順番**:歴史の会戦の結果の処理が、都市の持ち主を変える**前**に呼ばれていました。そのため洛陽を落としても「洛陽は持ちこたえた」と判定され、「洛陽を失った」の印も付きませんでした。いまは、都市・人物・首都の処理がすべて終わってから読みます。
2. **懐帝の捕縛**:実際の所在ではなく、「住まい」の項目で決めていました。いまは、首都の陥落と同じ処理で、懐帝が**実際に洛陽にいれば**捕らえます。事件の側で二度目の捕縛はしません。
3. **西晋が必ず滅びる問題**:捕縛のあと、ふつうの決まり(90%で滅亡)が当たっていました。事件ごとに「陥落したときの決まり」を書けるようにしました。永嘉の乱は「懐帝がいれば必ず捕らえる。後継者と残る都市があれば国は続く」です。ふつうの首都の陥落(捕縛80%・滅亡90%)は変えていません。
4. **国号**:君主が代わると、「漢(劉淵)」のような君主名入りの国号を、新しい君主の名に直します(セーブに残ります)。
5. **分岐の記録**:会戦の結果が史実と違ったとき(守り切った・君主がいなかった・脱出した)、事件の記録を「分岐」にします。

### 永嘉の乱の確かめ(テスト33)

304年の状態から、懐帝(司馬熾)が即位して洛陽にいる状況を作り、事件を起こしました(晋:洛陽にとどまる/漢:総攻撃)。洛陽の攻城戦は、戦闘のスキップで決着させています。

| 場面 | 結果 |
|---|---|
| 史実(漢が落とす) | 洛陽は漢のものになり、地図の色も変わった。懐帝は漢の捕虜(所在「漢の捕虜(離石)」)で、軍団は率いない。西晋は滅びず、後継者(この試行では司馬穎)が即位して残る都市で続く。年表に3行(選択・結果・会戦)。セーブ・ロード後も同じ |
| 西晋が守り切る | 洛陽は西晋のまま。懐帝は捕らえられない。事件は「分岐」 |
| 懐帝が長安にいた | 洛陽は落ちたが、懐帝は捕らえられない(瞬間移動させない)。「洛陽にいなかったので捕らえられなかった(史実との分岐)」と記録 |

### 57件全体の確かめ

**開始時の試行(テスト34)**

各シナリオの開始時(自由歴史のモード)に起こせる事件(16件)を、選択肢ごとに75通り起こしました。会戦を伴う事件は、テストの準備として両国の主力を戦場のそばに置き、その場の会戦を決着させています(9通り)。

そのたびに、次のことを調べました。

- 地図の色と都市の持ち主が合っているか
- 滅んだ国が都市を持っていないか
- 君主が健在か
- 死者・捕虜が軍団を率いていないか
- 滅んだ国の軍団が残っていないか
- 首都が自国の都市か
- 捕虜の記録と人物の状態が合っているか
- 瞬間移動・存在しない人物がないか
- セーブ・ロードで、国・都市・人物・軍団・首都・外交が変わらないか

**違反は0件**でした。史実どおりの選択で状態が何も変わらない事件(会戦・進軍を始めるものを除く)も、0件でした。

**通しの結果**

8シナリオを、次のシナリオの年まで史実重視のモードで進めました。自然に起きた事件ごとと30日ごとに、同じ整合の検査をしています(結果は対応表)。

57件の内訳は次のとおりです。

| 通しの結果 | 件数 |
|---|---|
| 史実どおりに起きた | 26件 |
| 分岐した(前の事件が史実と違った、など) | 26件 |
| 別の形ですでに起きていた | 2件 |
| 期間内に起きなかった | 3件 |

どの場合も、整合の違反は0件でした。

**通しで見つけて直したこと**

- **事件の会戦を始められなかったのに「史実どおり」と記録していた**(司馬越の権力掌握:会戦に出る軍団がなかった)。いまは「分岐」と記録します。
- **結果の文が出るだけだった事件**:変化の一覧が、1人の忠誠・名声、国どうしの友好度、摂政の変化を拾っていなかったため、変化0件に見えていました。いまは拾います。あわせて「石虎の権力掌握」は、石虎が後趙の摂政になり、軍を握り、国の安定が下がるようにしました。
- **捕虜の記録の食い違い**:
  - 会戦で戦死した人を「死亡」にするとき、捕虜の記録が残っていました。いまは死亡の処理に回します。
  - 捕虜を「負傷」で上書きしていました。いまは上書きしません。
  - 簒奪で殺された君主の記録が残っていました。いまは消します。
  - それでも383年からの通しで3人(褚蒜子・郤宣・何法倪)の食い違いが出たため、毎月、記録と状態を照らし合わせて片づける処理を入れました。**この3人の根の原因は、まだ突き止めていません。**

**主な事件の確かめ(テスト34-4)**

史実どおりの選択で、国・君主・都市が期待どおりに変わるかを確かめました。

- 開始時に起こせた事件で確かめたもの:
  - 長安の陥落:長安が漢に、司馬模の国が滅び、残りは後継国家へ。
  - 東晋の成立:安定+10。
- 開始時に起こせない事件(前の事件が前提)は、通しの結果で確かめました:靳準の乱、後趙の成立、石虎の簒奪、前燕の滅亡、北魏の成立、前秦の分裂。

57件の対応表(条件・史実の結果・分岐の結果・試行と通しの結果・検査):docs/v42-events57.md

## 4. 首都の陥落の仕組みとの整合

- **ふつうの攻城戦**:捕縛80%・捕縛のあと滅亡90%のまま変えていません。
- **事件の攻城戦**:事件に「陥落したときの決まり」があれば、それに従います(いまは永嘉の乱だけ)。後継者と残る都市の処理は、首都の陥落と同じものを使います。
- **二重の処理を防ぐ仕組み**:
  - 君主の捕縛は、首都の陥落の処理が1度だけ行う。
  - 事件の処理は結果を読むだけ。
  - 事件の捕縛は、すでに捕虜なら何もしない。
  - 都市の移転は、すでに同じ持ち主なら何もしない。
