# 『五胡乱華』Version 54 の報告:写実寄りの3Dの人物

この報告の「確かめた」は、すべて開発環境の自動テストの結果です。
- 自動テストは、Playwright と Chromium で動かしています。
- 描画は SwiftShader です。これは GPU を使わない、ソフトウェアでの描画です。
- **実機(LG gram・iPhone)では、まだ何も確かめていません。**
- 画像はすべてソフトウェア描画で撮ったもので、実機のスクリーンショットではありません。

## 結論

- 顔は、球に絵を貼る作り方をやめ、形を持った3Dの顔にしました。素材は MakeHuman(CC0)です。
  - 鼻・まぶた・唇・耳・眼球(虹彩と角膜)・まつげがあります。
  - 8つの表情・まばたき・話す口が、モーフで動きます。
- **添付の画像(写実の肖像)の品質には、まだ届いていません。** 肌の質感、髪(毛の束)、顔の魅力の点で、差がはっきり残っています。
- そのため、**指示のとおり、全員への展開は既定にしていません**。
  - 既定は「試作の3人」(皇后・妃・女官を1人ずつ)です。
  - 画面の「顔」のボタンで「全員」「従来」にも切り替えられます。
- 全員を既定にするかは、比較画像を見て決めてください。

## 1. 顔のモデルの変え方

| | Version 53 | Version 54 |
|---|---|---|
| 顔の形 | 球1つ(三角形 約360) | MakeHuman の人体の頭と首(三角形 8,692) |
| 目・鼻・口・耳 | 絵の線だけ | 形がある。まぶた・鼻翼・鼻孔・唇・耳 |
| 眼球 | なし | 高精細の眼球と虹彩の絵、透明な角膜(つや) |
| まつげ | なし | まぶたの縁から、反った毛の帯を作り、毛の絵を貼る |
| 眉 | 線 | 肌の絵に、毛を1本ずつ描く(柳の葉の形) |
| 肌 | Lambert(光沢のない単純な陰影) | PBR(MeshPhysicalMaterial)。色の絵・粗さの絵・柔らかい光沢(sheen)・周りの光(環境マップ) |
| 表情 | 絵の描き替え | モーフターゲット(MakeHuman の表情の単位を組み合わせる) |
| 人ごとの違い | 線の3種類 | 顔の形の20種の量を、人ごとに混ぜる(輪郭・頬・顎・鼻・唇・目・眉・年齢) |
| 髪 | 球 | 頭の形に沿った殻(生え際は毛先が消える)、鬢(こめかみの髪)、身分ごとの結い髪 |
| 読み込み | なし | GLB(glTF 2.0)を、ゲームの中に埋め込んで読む(3.6MB) |

GLB は `tools/v54/build_heads.py` で作ります。Python と numpy・Pillow だけで動き、Blender は使っていません。
- 頭の切り出し、UV の詰め直し(頭だけの 2048×2048 の絵にする)、肌の絵の塗り、モーフの書き出しをします。
- 体は、Version 53 の衣装の体のままです。首の付け根に、新しい頭を付けます。

## 6. 顔・髪・衣装の改善点

- **顔:** 本物の頭の形を持ちます。顔の形は人ごとに違い、年齢(40代の女官など)も出ます。
- **化粧:** 身分で3種あります。
  - 皇后:濃い紅・目元の紅・額の花鈿
  - 妃:桃色の頬と目元
  - 女官:控えめ
- **髪:** 頭の形に沿わせ、生え際は毛先が消えるようにしました。こめかみの鬢を足しました。
  - 皇后:高髻(二つの輪)・金の冠・歩揺(真珠の房)・額の真珠の弧
  - 妃:双環の髻・玉の簪・額の細い真珠
  - 女官:後ろで低く一つに結い、銀の簪
- **衣装:** Version 53 のままで、変えていません。

## 7. 表情と動き

- 8つの表情で、顔の形が崩れないことを確かめました(試験40 H3)。
  - 位置はすべて有限で、動く量は最大 1.3cm です。
  - 表情は、なめらかに移ります。
- まばたきは、3〜6秒に一度です。話すときは、口を開け閉めします(あ・お)。
- 歩く・座る・拝礼・話すときも、写実の頭は付いたまま動きます(試験40 H4)。
- 会話中は、カメラが相手の顔に約1.3mまで寄ります。顔は、画面の上の方に来ます(試験40 H6)。

## 8. FPS(ソフトウェア描画・1280×800、6人を近くに並べたとき)

| 画質 | 従来の顔 | 写実の顔(全員) | 写実の頭の数 | 三角形 |
|---|---|---|---|---|
| 低 | 4.8 | 4.4 | 1 | 26.8k → 42.6k |
| 中 | 3.2 | 2.6 | 4 | 78.6k → 201.5k |
| 高 | 2.8 | 2.2 | 7 | 78.7k → 278.9k |

- 写実の頭は、1人で約1.6万の三角形です。結い髪の分割を減らして、2万から下げました。
- ソフトウェア描画では、塗る手間が大きいため遅くなります。
- **LG gram の中画質で 30FPS は、実機で確かめていないので、達成したとは言えません。**

## 9. メモリが増えた原因と、直した結果

- **原因:** オートセーブの書き込み待ちが、たまっていました。
  - 時を早く進めると、セーブを始める速さが、書き終わる速さ(1件 約0.5秒)を上回っていました。
  - その結果、書き込みを待つセーブの写しが、たまっていました。
  - ヒープの記録とたどりで確かめました(docs/v54-stage1-analysis.md)。
- **直したこと:** 書き込みは、一度に一つだけにしました。途中に来た保存は、最新の状態を一度だけ書きます。
- **結果(同じ条件、ごみ集めのあと):**
  - 直す前:20年で 178MB → 506MB
  - 直したあと:40年で 178MB → 192MB(190MB 前後で止まる)
- 写実の頭の資源について:
  - 宮殿との往復10回(毎回、写実の頭を付ける)で、形・絵の数は増えません(試験40 H7)。
  - 共有の素(GLB)は、一度読み込んだら残します。
  - 人ごとの頭は、離れたとき・宮殿を出たときに片づけます。
  - 周りの光(環境マップ)を片づけ忘れる漏れを見つけ、直しました。

## 13. 実機での確かめ方

docs/v53-device-test.md の手順に、次を加えてください。
- 宮殿の右の「顔」ボタンで、「試作の3人 → 全員 → 従来」と切り替える。
- 人物に近づき、顔が写実の頭に変わるか、離れると戻るかを見る。
- 話しかけて、カメラが顔に寄るか、顔が交流の欄に隠れないかを見る。
- 「顔:全員」「画質:中」で、庭園に人が集まった所の FPS を測る(LG gram は目標 30FPS)。
- iPhone は、画質「低」(写実の頭は1人まで)で、熱くならないか、落ちないかを見る。
