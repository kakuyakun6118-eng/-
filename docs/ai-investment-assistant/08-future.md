# 8. 将来の拡張方針

**この章で決めること:** 将来どう広げられるか。有料化が必要なものは選択肢として整理します。
**有料の選択肢は、導入前に必ず費用を報告して承認をいただきます。勝手に導入はしません。**

## 8.1 最初から入れておく拡張しやすい作り
| 工夫 | 効果 |
|---|---|
| 計算を `domain/` に集約 | テストしやすく、画面やDBを変えても計算は再利用できる |
| データ取得を `providers/` で差し替え可能に | 無料→有料、別サービスへの乗り換えが1ファイルで済む |
| AIを `ai/providers/` で差し替え可能に | Claude Code → Claude API の切り替えが設定変更で可能 |
| 価格の出典に優先順位 | 有料データを追加しても既存の仕組みのまま使える |
| `calc_version` / `prompt_version` の記録 | 計算・プロンプトの改良を追跡できる |
| SQLite → 別DBへ移行可能な設計(SQLAlchemy) | 将来クラウド化する場合も移行しやすい |

## 8.2 無料のまま追加できる拡張
| 内容 | 備考 |
|---|---|
| バックテスト・相関分析・効率的フロンティア・モンテカルロ | Python で実装(pandas / numpy) |
| リバランス提案 | 目標配分との差から売買金額を計算 |
| ストレステスト | 円高10%・株価−30%・金利上昇などの資産影響 |
| EDINET の有報テキストの要約(事業リスクの変化) | Claude Code で手動実行 |
| 年間損益レポート・損出し候補 | 計算のみ |
| Gmail(無料)でのメール通知 | アプリパスワードを使用 |
| 仮想通貨(取引所の読み取り専用API・無料のもの) | 必要になれば |
