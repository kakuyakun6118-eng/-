# 7. セキュリティ設計

**この章で決めること:** 資産情報(極めて機密性が高い個人情報)とAPIキーをどう守るか。

---

## 7.1 守るべきもの

| 対象 | 漏れた場合の影響 | 対策の重要度 |
|---|---|---|
| 資産・取引データ | 資産額・保有銘柄が他人に知られる | 最高 |
| APIキー(Claude・株価API) | 不正利用で高額請求 | 最高 |
| ログイン情報 | 全データへのアクセス | 最高 |
| 証券会社のID・パスワード | **本システムでは一切保存しない** | — |

---

## 7.2 認証(ログイン)

- Supabase Auth のメール + パスワード認証
- **2段階認証(TOTP:認証アプリのワンタイムコード)を必須**にする
- **新規ユーザー登録を無効化**(自分のアカウントのみ。Supabaseの設定でサインアップをオフ)
- パスワードは12文字以上、パスワードマネージャーの利用を推奨
- セッションは一定時間で失効、他端末のログアウト機能
- ログイン失敗の回数制限(Supabase標準 + 必要に応じて追加)

## 7.3 データへのアクセス制御

- **行レベルセキュリティ(RLS)をすべての個人データ表で有効化**
  例: `transactions` は `user_id = auth.uid()` の行しか読み書きできない
- 共通データ(株価・財務・マクロ)は「ログイン済みなら読み取り可、書き込みはサーバーのみ」
- RLSのテストを書く(他ユーザーとしてアクセスして読めないことを確認)
- ブラウザに渡すのは Supabase の「公開用キー(anon key)」のみ。RLSが前提なので漏れても他人はデータを読めない

## 7.4 APIキー・秘密情報の管理

| 秘密情報 | 保管場所 | ブラウザに渡すか |
|---|---|---|
| Claude APIキー | Vercel の環境変数(暗号化保管) | **渡さない**(サーバー側のみで使用) |
| 株価・財務APIキー | Vercel の環境変数 | 渡さない |
| Supabase service_role キー(管理者権限) | Vercel の環境変数(定期ジョブのみ使用) | **絶対に渡さない** |
| 定期ジョブ用の秘密トークン | Vercel + Supabase Vault | 渡さない |

- Next.js では `NEXT_PUBLIC_` で始まる環境変数だけがブラウザに送られる → 秘密情報には絶対に付けない
- サーバー専用のコードには `server-only` パッケージを読み込み、誤ってブラウザ側で使うとビルドエラーにする
- `.env.local` は `.gitignore` に入れ、GitHub に上げない。`.env.example`(値なし)だけ共有
- GitHub のシークレットスキャン(Push Protection)を有効化
- Claude・株価APIには**月額の利用上限**を各サービスの管理画面で設定(万一の漏えい時の被害を限定)
- キーは年1回、または漏えいの疑いがあれば即座に再発行

## 7.5 通信・アプリの安全性

- HTTPS のみ(Vercel標準)
- セキュリティヘッダー: CSP(読み込み可能な外部リソースを制限)、HSTS、X-Frame-Options 等
- 入力値はすべて Zod で検証、DB操作はパラメータ化(SQLインジェクション対策)
- 定期ジョブのAPIは秘密トークンの一致を確認し、それ以外は拒否
- 依存パッケージの脆弱性チェック(Dependabot)

## 7.6 AI利用時の注意

- Claude に送るデータは分析に必要な最小限(氏名・口座番号・証券会社のログイン情報は送らない)
- 金額は分析に必要な範囲で送る(比率のみで足りる場面は比率にする)
- Anthropic の API は既定でAPI入力をモデル学習に使用しない(公式のデータ利用ポリシーを実装時に再確認)
- **プロンプトインジェクション対策:** ニュース記事などの外部テキストは「データ」として区切って渡し、その中の指示には従わないようシステムプロンプトで指示。AIの出力は検証してから保存(09章)

## 7.7 バックアップと復旧

- Supabase の自動バックアップ(Freeプランは制限あり → 週1回、取引データを自分でエクスポートする機能を用意)
- 取引データのCSVエクスポート機能(Phase 1で実装)
- 削除は「論理削除(削除フラグ)」+ 監査ログで復元可能に

## 7.8 端末側の注意

- iPhone・PC の画面ロックを有効に
- 共有PCではログインしない
- ブラウザにパスワードを保存する場合は端末自体のロックを必須に
