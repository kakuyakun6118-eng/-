# NY旅のしおり

2026/9/18〜9/23 のニューヨーク旅行用、夫婦2人で共有できる旅のしおりアプリです。
旅程づくりから、旅行中に使う英会話フレーズの練習まで、1つのアプリにまとめています。
Googleマップでピンを立てた「行きたい場所」を登録し、日程に割り振ってスケジュール化、
読みやすい「しおり」として2人のiPhoneでいつでも見られるようにします。

## できること

- 📍 **場所**: 場所名・カテゴリ・優先度・エリア・GoogleマップのURL・メモを登録。
  **まとめて取り込み**にも対応(下記)
- ✨ **AI提案**: 登録した場所から日程を自動作成。曜日・時間帯の混みやすさ、休館日、
  エリアのまとまり、移動時間、食事の時間まで考慮します
- 🗓️ **予定**: 日付ごとに時刻・所要時間・メモを付けて手動でも調整可能
- 📖 **しおり**: 宿泊先情報つきで、日別にきれいな一覧表示。共有ボタンでLINE/iMessageに送れる
- 🗣️ **英会話**: 旅行中に使う98フレーズを、クイズ形式で出発までに覚えられます(下記)
- ⚙️ **設定**: 出発日・帰国日・宿泊先情報を編集
- 📱 iPhoneのホーム画面に追加してアプリのように使える(PWA)
- 🔄 Firebaseを設定すると、夫婦のiPhone2台でリアルタイムに同じデータを共有できる

Firebase未設定の状態でもアプリ自体はすぐ使えます(その場合は自分の端末だけに保存されます)。

## 旅の英会話(フレーズ学習)

「英会話」タブは、旅行中に実際に口に出すフレーズを、出発までにクイズで覚えるための機能です。
フレーズと出題はすべて端末内で完結しているので、**飛行機の中や地下鉄などオフラインでも使えます**
(読み上げにはiPhone内蔵の音声合成を使います)。

### 入っているフレーズ

空港・入国審査 / ホテル / レストラン・カフェ / 地下鉄・タクシー / 買い物 / 観光・チケット /
あいさつ・雑談 / 困ったとき の8シーン、**全98フレーズ**。
それぞれに日本語・英語・カタカナ読みに加えて、「チップは18〜20%」「bill ではなく check」
「uptown / downtown」といった**現地でつまずきやすいポイント**と、
**相手から返ってきそうな一言**を添えてあります。

### 5種類の出題

| 形式 | 内容 |
| --- | --- |
| 日本語 → 英語 | 言いたいことから英文を4択で選ぶ |
| 英語 → 日本語 | 聞こえた・見えた英文の意味を選ぶ |
| 聞き取り | 読み上げられた英文を4択で選ぶ(ゆっくり再生あり) |
| 並べかえ | 単語をタップして英文を組み立てる |
| 穴うめ | 英文の空欄に入る単語を選ぶ |

覚えたてのフレーズはやさしい4択から、正解を重ねると並べかえや穴うめといった
「自分で組み立てる」出題に切り替わります。はじめて出るフレーズは、
いきなり問題にせず先にフレーズカードで紹介します。

### 忘れたころに出しなおす仕組み

1つのフレーズごとに、正解するたび **当日 → 1日後 → 2日後 → 4日後 → 7日後 → 14日後** と
出題間隔が延びていきます。まちがえた分はその場でもう一度出題し、翌日以降の復習にも戻します。
ホームの「復習」ボタンには、いま出しなおすべきフレーズの件数が出ます。

### 続けたくなる仕掛け

- 正解でXPが貯まり、連続正解(コンボ)でボーナス。100XPごとにレベルアップ
- 1日の目標問数と、連続学習日数(🔥)
- 出発日から逆算した「1日◯フレーズ覚えれば全部持っていけます」の目安
- **2人の記録**を並べて表示。夫婦それぞれの学習記録は別々に貯まります
- 「場所」タブに登録した行き先の傾向から、練習するシーンを提案

画面右上の名前(わたし/妻)をタップすると学習者を切り替えられます。名前は
「学習の設定」から変更できます。Firebaseを設定していれば、2台のiPhoneで
お互いの進み具合が見えます。

### フレーズを足したいとき

[`src/phrases/data.ts`](src/phrases/data.ts) の `PHRASES` に1件追加するだけです
(`id` は一度公開したら変更しないでください。学習の記録が `id` にひもづいています)。

> ℹ️ **すでに使っているアプリにそのまま追加できます。** 学習記録は旅行データと同じ
> ドキュメントに保存するので、Firebaseコンソールでのルールの貼り直しは不要です。
> 共有サーバーに書き込めなかった場合も、記録はその端末に残したまま学習を続けられます。

## 場所のまとめて取り込み

1件ずつ手入力しなくても、3つの方法でまとめて登録できます。
どの方法でも、保存する前に一覧で名前・カテゴリ・優先度を直せます。

### 1. Googleマップの保存リストから(いちばん確実)

[Google データエクスポート](https://takeout.google.com/) で
**「保存済み」** と **「マップ(マイプレイス)」** の2つを選んでエクスポートします。

- 「保存済み」→ **自分で作ったリスト**(「ニューヨーク行きたい」など)が **CSV**(`Title,Note,URL`)
- 「マップ(マイプレイス)」→ **保存した場所**が **JSON**(GeoJSON。住所つき)

**この2つは別物です。** 自分で作ったリストは「保存済み」にしか含まれないため、
「マップ(マイプレイス)」だけを選ぶと、リストが取り込めません。逆に、
星を付けただけの場所は「マップ(マイプレイス)」側に入ります。両方選ぶのが確実です。

**届いたzipファイルをそのままアプリで選ぶだけです。解凍は不要です。**
zipの中から場所データのファイル(`.csv` / `.json`)を自動で探し、
`archive_browser.html` などの不要なファイルは読み飛ばします。
解凍済みのCSV/JSONを直接選んでも構いません(複数まとめて選択可)。

どちらの形式でも取り込めるので、両方選んでおけば確実です。
名前・GoogleマップのURL・(JSONなら)住所から推定したエリアまで入ります。

名前らしき列があるCSVなら形式は問いません(`Title`/`name`/`名前` などを自動判定)。

2つの形式には同じ場所が重複して含まれます。取り込み時に、
**同一バッチ内の重複は自動で除去**し、**すでに登録済みの場所には「登録済み」と表示して
チェックを外した状態**にします(名前の大文字小文字・全角半角・記号の違いは無視して判定)。

### 2. まとめて貼り付け

1行1件でテキストを貼り付けます。行頭の `-` や `1.` は自動で除去され、
行内にGoogleマップのリンクが混ざっていても分離して取り込みます。
`https://www.google.com/maps/place/High+Line/...` のような完全なURLだけの行は、
URLから場所名を復元します(`maps.app.goo.gl` の短縮リンクは名前を含まないため復元できません)。

### 3. スクショから読み取り(複数枚可)

Googleマップで場所を開いた画面のスクリーンショットを複数枚まとめて選べます。
端末内で文字認識(OCR)を行い、**いちばん大きな文字**を場所名として推定します。
誤読しやすいので、他の候補もタップ1回で選べるようにしてあります。

- 初回のみ文字認識データ(数MB)をネットワークから取得します
- 認識精度は画像の状態に左右されます。**必ず保存前に確認・修正してください**
- 精度と手間の両面で、可能なら方法1か2をおすすめします

いずれの方法でも、場所名からカテゴリ(食事・美術館・公園など)を自動推定します。

## AI提案(自動スケジュール)の仕組みと限界

**重要: 混雑状況・空き状況のリアルタイムデータは使っていません。**

Googleマップの「混雑する時間帯」を外部から取得できる公式APIは提供されておらず、
美術館の開館時間やチケットの空き枠を横断的に取得できる無料の手段もありません。
そのため本アプリの混雑予測は、次の要素から**統計的に推定した目安**です。

- 曜日(土日は混む、平日午前は空きやすい、月曜は休館が多い など)
- 時間帯(美術館は昼過ぎがピーク、レストランは12〜14時と19〜21時がピーク など)
- 場所のタイプ(展望台は日没前後が最混雑、公園は混雑の影響が小さい など)
- 旅行時期(9月下旬は国連総会で国連本部周辺が交通規制されやすい など)

有名スポットについては所要時間・休館日の初期値を内蔵していますが、これらは
変更される可能性があるため、アプリ上でも「要確認」と表示されます。
**実際の休館日・営業時間・予約可否は必ず公式サイトでご確認ください。**

各場所の編集画面にある「AI提案の詳細設定」から、定休日・所要時間・おすすめ時間帯・
要予約を手動で上書きできます。正しい情報を入れるほど提案の精度が上がります。

## 写真について

ヘッダーとしおりの日別バナーには、ニューヨークの写真7枚を同梱しています。

**日別バナーは、その日の予定に入っている行き先に合わせて自動で選ばれます。**
自由の女神を回る日は自由の女神の写真、セントラルパークの日は公園の写真、
という具合です。予定を組み替えるとバナーも自動的に追従し、同じ写真が
複数の日で重複しないよう1日1枚ずつ割り当てられます。

写真の差し替え・追加の手順は
[`public/photos/README.md`](public/photos/README.md) を参照してください。
写真が見つからないシーンは、内蔵のイラストに自動でフォールバックします
(オフラインでも表示できます)。

## 2人で共有するためのFirebase設定(所要5〜10分)

共有機能には無料のFirebaseプロジェクトが必要です。どちらか一方(母艦)が1回だけ作業すればOKです。

1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログイン
2. 「プロジェクトを作成」→ 適当な名前(例: `ny-trip`)を入力 → Google Analyticsは無効でOK
3. 左メニュー「構築」→「Firestore Database」→「データベースの作成」
   - ロケーションは `nam5` (us-central) など任意
   - セキュリティルールは「本番環境モード」でOK(あとで上書きします)
4. 「ルール」タブを開き、このリポジトリの `firestore.rules` の内容を貼り付けて公開
5. 左メニュー「構築」→「Authentication」→「始める」→「Sign-in method」タブで
   **「匿名」を有効化**(ログイン画面なしで2人がすぐ使えるようにするためのものです)
6. 左メニューの歯車 →「プロジェクトの設定」→ 下の方の「マイアプリ」→ `</>`(ウェブ)を選択して
   アプリを登録すると `firebaseConfig` が表示されます。これをメモしておきます

### ローカルで試す場合

`.env.example` を `.env.local` にコピーし、`firebaseConfig` の値を転記して `npm run dev` を再起動。

### 公開版(GitHub Pages)に設定する場合

このリポジトリの GitHub の Settings で設定します。

1. **Settings → Secrets and variables → Actions → Secrets** に以下を1つずつ追加
   - `VITE_FIREBASE_API_KEY`
   - `VITE_FIREBASE_AUTH_DOMAIN`
   - `VITE_FIREBASE_PROJECT_ID`
   - `VITE_FIREBASE_STORAGE_BUCKET`
   - `VITE_FIREBASE_MESSAGING_SENDER_ID`
   - `VITE_FIREBASE_APP_ID`
2. (任意) **Secrets and variables → Actions → Variables** に `VITE_TRIP_ID` を追加(未設定なら `ny-2026-09` が使われます)
3. **Settings → Pages** で Source を **「GitHub Actions」** に変更
4. `main` ブランチに push すると `.github/workflows/deploy.yml` が自動でビルド・公開します
   (このブランチの変更を取り込む場合は、一度 `main` にマージしてください)
5. 数分後、`https://<あなたのGitHubユーザー名>.github.io/-/` でアクセスできるようになります

Secretsを設定していない状態でもデプロイ自体は成功しますが、その場合は各端末のローカル保存のみ
(2台で共有されません)。あとから設定してもう一度pushすれば共有が有効になります。

## iPhoneのホーム画面に追加する

1. SafariでアプリのURLを開く
2. 共有ボタン(□に↑)をタップ
3. 「ホーム画面に追加」を選択

夫婦それぞれの iPhone で行うと、アプリのようにアイコンから起動できます。

## データの持たせ方について(補足)

- 共有は「匿名認証 + Firestoreルール」による簡易的なものです。URLとプロジェクトの組み合わせが
  第三者に知られない限りは夫婦2人だけのデータですが、パスワード等はありません。旅行のしおり用途
  としては十分な想定ですが、機密情報の保存には向きません。
- Googleマップの「保存済みリスト」を直接読み込む公式APIはないため、ピンを立てた場所は
  アプリ内で手動登録する方式にしています(名前・メモ・GoogleマップのURLをコピペするだけでOK)。

## 技術構成

- GitHub Actions → GitHub Pages(自動デプロイ)
