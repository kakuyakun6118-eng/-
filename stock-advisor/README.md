# 株価インパクト・アドバイザー

ニュース見出しとテクニカル指標をもとに「今日のおすすめ銘柄(ウォッチリスト)」と「保有株の売り/継続」の参考情報を表示する、個人利用向けの Next.js アプリです。

**これは投資助言ではありません。** 表示される判定はルールベースとLLMによる参考情報であり、正確性・妥当性を保証しません。実際の売買判断はご自身の責任で行ってください。第三者への提供・販売は金融商品取引法上の投資助言業規制の対象になり得るため想定していません。

## 構成

元の設計図(X投稿の取得 → 銘柄コード抽出 → LLM解釈 → 株価API → ダッシュボード/通知)から、このMVPでは以下を実装しています。

| 段階 | 元の設計 | このMVPでの実装 |
| --- | --- | --- |
| 情報収集(ニュース) | X (Twitter) API | **Google News RSS**(無料・APIキー不要)。`src/lib/news.ts` の `NewsSource` インターフェースを実装すれば、有料の X API 契約後に差し替え可能 |
| 情報収集(注目アカウント) | X (Twitter) API | `src/lib/socialSource.ts` で X API v2 を直接利用。`data/watchedAccounts.json` に列挙したアカウント本人の公開投稿をそのまま取得・引用します(発言の生成・要約は行いません) |
| 銘柄コード抽出 | バックエンド処理 | ウォッチリスト(`data/watchlist.json`)・保有株(`data/holdings.json`)から直接ティッカーを指定する方式に簡略化 |
| 解釈・影響度判定 | Claude/OpenAI API | 2系統。`/watch` は**紫蘇の葉理論**(`src/lib/theory.ts` + `src/lib/theoryPrompt.ts`)、`/` と `/holdings` は汎用のニュース影響度判定(`src/lib/llm.ts` + `src/lib/newsPrompt.ts`)。入力が「監視アカウントの投稿」と「一般ニュース見出し」で異なるため分けています |
| 株価データ | yfinance | `yahoo-finance2`(Node製、日本株ティッカー `XXXX.T` に対応) |
| ダッシュボード | Next.js | 実装済み(`/` = おすすめ一覧、`/holdings` = 保有株管理・売り時判定) |
| 通知 | Discord/LINE | 未実装(必要であれば `src/lib/scoring.ts` の出力を通知先に送るジョブを追加してください) |

## セットアップ

```bash
cd stock-advisor
npm install
cp .env.example .env.local
# .env.local に ANTHROPIC_API_KEY(・任意でX_BEARER_TOKEN)を設定
npm run dev
```

[http://localhost:3000](http://localhost:3000) で起動します。`ANTHROPIC_API_KEY` が未設定の場合、ニュース影響度判定はスキップされ「中立」表示になります(アプリ自体は動作します)。

テストは `npm test` で実行できます(ネットワーク不要)。

### キャッシュについて

1画面の表示につき「株価取得 × 銘柄数」「ニュース取得 × 銘柄数」「LLM判定 × 銘柄数」の外部呼び出しが発生するため、`src/lib/cache.ts` のTTLキャッシュを挟んでいます(株価60秒 / ニュース15分 / LLM判定30分 / X投稿10分)。LLM判定のキャッシュキーには見出し内容のハッシュを含めているので、新しいニュースが出れば自動的に再判定されます。API障害時の結果はキャッシュされません。

プロセス内メモリのキャッシュなので再起動で消えます。個人利用では十分ですが、複数インスタンスで運用する場合はRedis等に差し替えてください。

## 使い方

- **`/`(今日のおすすめ)**: `data/watchlist.json` に列挙した銘柄について、株価変動・出来高・ニュース影響度を組み合わせたスコアで並べ替えて表示します。ウォッチリストはJSONを直接編集して増減できます。
- **`/holdings`(保有株)**: 銘柄コード・株数・取得単価を手入力で登録すると(`data/holdings.json` に保存)、「売り時を判定する」ボタンで現在値・含み損益・ニュース影響度を踏まえた 売却検討/様子見/継続保有 の参考情報を表示します。
- **`/watch`(注目アカウントの投稿)**: `data/watchedAccounts.json` に列挙したXアカウント本人の直近投稿を取得し、投稿本文から抽出した銘柄コードごとに後述の**紫蘇の葉理論スコア**を表示します。**表示されるのは本人の実際の投稿の引用のみで、AIがその人物になりすまして発言を生成することはしません。**

## 紫蘇の葉理論スコア

`/watch` の判定ロジックです。3つのルールの合計点(-30〜+70点)で評価します。

| ルール | 配点 | 判定方法 |
| --- | --- | --- |
| 1. 話題性の急上昇 | +30 | **実測**(`src/lib/theory.ts`)。監視アカウントによる直近24時間の言及数が、同アカウントの通常時の1日あたり言及数の3倍以上か |
| 2. ポジティブ感 | +40 | **LLM判定**(`src/lib/theoryPrompt.ts`)。「業績予想の上方修正」「新技術・新サービス」「好決算」など具体的な好材料に基づく言及か |
| 3. リスクの有無 | -30 | **LLM判定**。「イナゴ集め(過熱感のある煽り)」「公募増資」「不祥事」などの減点要素を含むか |

**ルール1をLLMに判定させていないのは意図的です。** 言及数の増加は数えられる量なので、推測させるより実際に数えたほうが正確です。ルール2・3は文意の解釈が必要なのでLLMが担当します。

判定結果は各ルールの内訳(該当/非該当・配点・根拠)まで画面に表示されるので、なぜその点数になったかを追えます。合計点は `strong`(40点以上)/ `watch`(10点以上)/ `neutral`(0点以上)/ `caution`(マイナス)の4段階に振り分けられます。

### ルール1の実測に関する注意

- 「通常時」の基準値は、取得した投稿ウィンドウ(最大100件)のうち**直近24時間より前の期間**から算出します。この期間が1日分に満たない場合は「判定不能」として0点にします(誤った基準で加点しないため)。
- 過去に一度も言及がなかった銘柄は「3倍」が計算できないため、直近24時間に2件以上の言及があった場合のみ「新規の話題」として加点します。1件だけの言及で満点が入るのを防ぐためです。

### 配点設計上の注意点(実装者からの指摘)

合計40点になるケースが2通りあります: 「話題性 +30 / 好材料 +40 / リスク -30」と「話題性 0 / 好材料 +40 / リスク 0」です。前者は**煽りを伴う急騰銘柄**、後者は**地味だが好材料のある銘柄**で、性質がかなり違うのに同じ点数・同じ `strong` 判定になります。運用してみて区別したくなった場合は、`src/lib/theory.ts` の `verdictFor()` を合計点ではなく内訳の組み合わせで分岐させてください。

## 制約・既知の限界

- ニュース情報源はGoogle News RSSのみで、X投稿由来の一般ニュースは取得していません(`/watch` の注目アカウント機能のみ、X API経由で当該アカウント本人の投稿を直接取得します)。
- `/watch` の銘柄コード抽出は、`7203.T`・`【7203】`・`(7203)`・`$7203`・`証券コード7203` のような明示的な記法を優先して拾います。裸の4桁数字は、ウォッチリストか保有株に含まれる銘柄の場合のみ採用し(かつ `2025年`・`3000円`・`100株` のような単位が続く場合は除外)、日付や価格の誤検出を抑えています。それでも記法なしの言及は取りこぼす可能性があります。
- 特定個人・アカウントの投稿内容に追随した売買は、その人物側の都合(利確・撤退等)で値動きが急変するリスクがあります。`/watch` の情報も他の画面と同様、投資助言ではなく参考情報です。
- 紫蘇の葉理論のルール1(話題性)は、X APIから取得できる投稿ウィンドウ(最大100件)の範囲でしか基準値を算出できません。投稿頻度が高いアカウントでは100件が数日分にしかならず、基準期間が短くなる点に注意してください。長期の基準値が必要な場合は、日次で言及数を記録する仕組みを追加する必要があります。
- Discord/LINE通知は未実装です。
- 保有株・ウォッチリスト・監視アカウントはローカルJSONファイルに保存されます(認証や複数ユーザー対応はありません)。個人利用を前提としています。
